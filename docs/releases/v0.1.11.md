# KubePhos v0.1.11

## Application placement and recovery

- Edit node selectors and tolerations on independent application deployments,
  including while provisioning is waiting for workloads to become ready.
- Live edits preserve managed placement constraints and use the verified package
  installed by the deployment, rather than a newer catalog definition.
- Retry failed deployments with their saved settings and namespace. Cleanup is
  restricted to resources owned by the previous attempt, including every member
  of a multi cluster group. Namespace reservations remain in force during Retry.
- Application pool selectors suggest `kubephos.dev/pool` in the Key field.

## Resource controls

- CPU and memory fields now have a unit selector to the right of the value, for
  both application containers and Istio proxies. Empty fields initially select
  Millicores and Mebibytes without assigning resource values.
- Existing quantities retain their units. Changing units converts the value
  without changing its amount; fractional cores are supported.
- The proxy resource Defaults tab reads requests and limits from the selected
  cluster's installed Istio injector. Multi cluster groups keep Istio disabled.

## Upgrade

Back up the installation and wait for active work to finish. Set
`KUBEPHOS_VERSION=v0.1.11` in the installation `.env`, then run `./update.sh` from
the v0.1.11 archive or checkout. Add `--directory /path/to/installation` for a
custom installation path. If using a temporary local image, restore
`KUBEPHOS_IMAGE=ghcr.io/unict-cclab/kubephos` first.

No new database migration is required. Existing configurations, suites,
experiments, credentials and managed resources are retained.

## Verification

479 frontend tests; Go tests and static analysis; isolated PostgreSQL tests for
storage, API and experiment execution; race checks for application deployment;
production frontend build, theme contrast, asset budget and dependency audit.
Authenticated browser checks verified resource units, exact conversion, the
installed injector defaults and the node selector placeholder. Live placement
and Retry were verified with automated tests; no application deployment was
started on the production cluster for verification.
