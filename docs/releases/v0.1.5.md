# KubePhos v0.1.5

## Compare existing results

The new **Comparisons** section groups completed runs from existing experiments
into series without launching new executions. Choose labels and colors, inspect
individual runs and use Statistics, Plots and Export with the same aggregation
as suites. A comparison supports up to eight series and eighty runs.

Comparisons are private. Source permissions are checked on every opening;
modifying or deleting a comparison leaves the source experiments untouched.
Deleted or inaccessible source runs must be removed from the comparison.
Differences in applications, load profiles, duration, resolution and monitoring
settings are highlighted. Each run retains its SLO target, and metrics with
inconsistent units are excluded from comparisons.

## Interface

- Replace native clone prompts with a dialog that preserves input after errors.
- Show short notifications at the top right, clear them on navigation and allow
  repeated errors to appear again. Success notifications use green.
- Keep cluster operation status in the Status column and diagnostics in Activity.
  Show deletion and retry validation immediately and use the current activity logs.
- Add Copy to manifests, Locust scripts and configuration snippets, including on
  HTTP installations. Remove the redundant Copy image action from strategies.

## Reliability

Fix resource creation failing after the connectivity schema update: template and
cluster workflow inserts now read the correct SQL return values. PostgreSQL
regression tests cover templates, clusters, Harbor and NFS.

Migration files now receive explicit readable permissions, including when a
package was extracted with a restrictive umask. The new comparison migration
adds its own table and index without changing suite execution or source results.

## Upgrade

Back up the installation and wait for active work to finish. Set
`KUBEPHOS_VERSION=v0.1.5` in the installation `.env`, then run `./update.sh` from
the v0.1.5 archive or checkout. Add `--directory /path/to/installation` for a custom
installation path. If using a temporary local image, first restore
`KUBEPHOS_IMAGE=ghcr.io/unict-cclab/kubephos`.

Migrations run automatically. Existing credentials, configurations and experiment
results are retained. Upgrade both instances before exporting a new state archive;
state transfer requires matching migration schemas and excludes result comparisons
along with experiment history.
