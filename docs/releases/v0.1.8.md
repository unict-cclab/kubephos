# KubePhos v0.1.8

## Application placement

- Configure **Labels and taints** for application pools when creating single or
  multi clusters. Master and Management retain their managed settings.
- Update application pool labels and taints through **Manage nodes** on single
  clusters when no experiments are queued or running. Settings persist across
  node restarts; changing them does not restart K3s.
- Use **Application → Placement** to configure a shared node selector and
  tolerations for experiment configurations and independent deployments.
- Override each service separately with **Inherit**, **Custom** or **None**.
  Custom replaces the shared custom settings for that service; None omits them.
  KubePhos-managed placement constraints are preserved in every mode, and
  conflicting selectors are rejected.

Pool labels and taints belong to the cluster and remain after each experiment
run. Pod selectors and tolerations are removed with the application and reapplied
on the next run. Existing configurations keep their previous placement behavior
until custom settings are supplied.

## Upgrade

Back up the installation and wait for active work to finish. Set
`KUBEPHOS_VERSION=v0.1.8` in the installation `.env`, then run `./update.sh` from
the v0.1.8 archive or checkout. Add `--directory /path/to/installation` for a custom
installation path. If using a temporary local image, restore
`KUBEPHOS_IMAGE=ghcr.io/unict-cclab/kubephos` first.

No new database migration is required. Existing configurations, suites,
experiments, credentials and managed resources are retained. Cleanup remains
compatible with application deployments created by v0.1.7.
