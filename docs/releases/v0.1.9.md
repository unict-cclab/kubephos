# KubePhos v0.1.9

## Interface and validation

- Grouped navigation for Infrastructure, Experiments and Administration, with
  section search, account controls and the running version in the sidebar.
- Resource details follow their editors' sections. Cluster editing uses a full
  page; application settings and service overrides use consistent named tabs.
- Clearer tables, compact controls, contained code snippets and consistent
  notifications in light and dark themes.
- Inline validation for required fields, resource quantities, placement conflicts
  and phase durations. Comparison actions explain missing prerequisites.
- Individual repetitions are called **Executions** in the interface. Existing
  API fields, stored results and export formats remain compatible.

## Application and node settings

- View generated node selectors and tolerations alongside custom application
  settings, and managed labels and taints alongside application pool settings.
- Edit application pool labels and taints on single or multi clusters while
  experiments or independent deployments are active. Topology changes retain
  their existing activity guards. Managed placement constraints remain protected.
- Configure optional Istio Envoy CPU and memory requests and limits, shared or
  per service, separately from application container resources.

## Upgrade

Back up the installation and wait for active work to finish. Set
`KUBEPHOS_VERSION=v0.1.9` in the installation `.env`, then run `./update.sh` from
the v0.1.9 archive or checkout. Add `--directory /path/to/installation` for a
custom installation path. If using a temporary local image, restore
`KUBEPHOS_IMAGE=ghcr.io/unict-cclab/kubephos` first.

No new database migration is required. Existing configurations, suites,
experiments, credentials and managed resources are retained.
