# KubePhos v0.1.6

## Experiment initialization

Configurations now support an optional application namespace and an editable
**Start mode**: **Automatic** or **Manual**. Existing configurations keep automatic
execution and generated namespaces.

Manual execution prepares the application and configured components, then waits
in **Initialized**. Select **Start** in the experiment detail or the play action in
the experiment list to begin traffic. Each repetition waits separately, including
runs in a suite. Waiting survives worker restarts and can be stopped with normal
resource cleanup. Start actions remain restricted to the owner and administrators.

A specified application namespace is deleted and recreated before each run and
removed during cleanup. System namespaces are protected, and concurrent runs on
the same cluster cannot use the same named namespace. Measurements exclude pods
from previous uses of the namespace.

## Application and network settings

- Enable or disable Istio injection for the application, with service overrides.
  HTTP applications default to enabled; native TCP applications retain their
  opt-out, and Cilium multi cluster groups do not use Istio.
- Configure network latency, jitter, bandwidth and packet loss in timed phases.
  Clone phases independently and validate their total against the load duration.
  Load and network phases share the same start time after initialization.
- New links are bidirectional by default. Latency applies independently in each
  direction; bandwidth remains the configured limit per direction. Existing
  saved links keep their direction and static profiles remain supported.

## Interface and reliability

Monitoring follows Load profile. Application settings select the first available
tab as parameters load while preserving explicit selections and entered values.
Phase actions use **Clone** and **Remove**, and compact field/value tables keep
labels and values aligned.

Successful empty `202 Accepted` responses no longer produce a false incomplete
response error when starting or stopping work. JSON responses and malformed
responses continue to be validated.

## Upgrade

Back up the installation and wait for active work to finish. Set
`KUBEPHOS_VERSION=v0.1.6` in the installation `.env`, then run `./update.sh` from
the v0.1.6 archive or checkout. Add `--directory /path/to/installation` for a custom
installation path. If using a temporary local image, first restore
`KUBEPHOS_IMAGE=ghcr.io/unict-cclab/kubephos`.

Migration 053 runs automatically. Existing credentials, configurations, suites and
results are retained. Existing experiments keep their frozen configuration.
State transfer requires matching migration schemas on both instances.
