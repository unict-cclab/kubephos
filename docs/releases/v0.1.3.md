# KubePhos v0.1.3

## Portable instance state

Administrators can now move infrastructure, catalog entries and reusable
configurations between KubePhos instances through **Administration → Export /
Import**.

- State archives are encrypted with a separate password.
- Exports include infrastructure connections and credentials, VM templates,
  clusters, Harbor/NFS records, application/model/strategy catalogs,
  configurations and suites, plugin settings and infrastructure access artifacts.
- Users, sessions, sharing permissions, experiments, collected results and the
  installation's `.env` are excluded.
- Import preserves infrastructure references and resource authorship. Credentials
  and sensitive artifacts are encrypted using the destination instance's key.
- Imported configurations are private and belong to the importing administrator.
  Duplicate configuration names are adjusted while retaining suite references.
- Import requires a fresh destination and a matching database migration schema.
  The archive is reviewed before confirmation. Failed imports roll back metadata
  and clean up temporary uploaded objects.

## Interface

- Separate **Export** and **Import** tabs, with short descriptions.
- Password confirmation appears below the archive password.
- Keyboard navigation, accessible labels and light/dark theme support.

## Upgrade

In the existing installation's `.env`, set `KUBEPHOS_VERSION=v0.1.3`, then run
`./update.sh` from this release directory or a clone at `v0.1.3`. For a custom
installation path, add `--directory /path/to/installation`.

Existing users, credentials and experiment history are retained when upgrading.
State transfer is separate from upgrading: it deliberately excludes experiment
history and does not copy VMs, container images or NFS/Harbor data. See the
[installation guide](https://github.com/unict-cclab/kubephos/blob/v0.1.3/docs/installation.md#move-instance-state-to-another-server)
for the migration procedure and full backups.

## Verification

Integration tests cover transfers between isolated PostgreSQL instances with
different encryption keys, user/experiment exclusions, suite references,
permissions, schema compatibility, rollback and object cleanup. Frontend checks
cover tab navigation, archive review, password validation and accessibility.
