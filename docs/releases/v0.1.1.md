# KubePhos v0.1.1

## Installation and updates

- Added `update.sh` to apply the installed `.env`, update images, migrate the
  database and restart services from any working directory.
- Changing `KUBEPHOS_URL` now updates Keycloak callback, web origin and logout
  redirects, preserving users and unrelated client settings. OIDC client secrets
  are synchronized before app and worker startup.
- Installation and update show high-level progress. Detailed Docker Compose output
  is saved in private `install.log` and `update.log` files; failures identify the
  phase and log path.
- Removed the bind-address setting. The application listens on all interfaces;
  `KUBEPHOS_PORT` selects the host port.
- Updates refuse to restart app and worker while experiments or operations are
  running. Installation files, credentials and persistent volumes are preserved.

## Upgrade from v0.1.0

Wait for running operations to finish and back up the installation as described in
[the installation guide](https://github.com/unict-cclab/kubephos/blob/v0.1.1/docs/installation.md).
Download and verify `kubephos-v0.1.1.tar.gz`, then extract it. In the existing
installation's `.env`, set `KUBEPHOS_VERSION=v0.1.1`, check `KUBEPHOS_URL` and
`KUBEPHOS_PORT`, and keep the existing credentials and Compose project name.
Run the updater from the extracted release:

```bash
/path/to/kubephos-v0.1.1/update.sh --directory /path/to/existing/installation
```

The updater installs the matching Compose file and copies itself into the
installation. Future configuration changes can be applied using that installed
`update.sh`. An old `KUBEPHOS_BIND_ADDRESS` entry is ignored and can be removed.
For legacy installations using a Keycloak master administrator named `admin`, add
`KUBEPHOS_KEYCLOAK_ADMIN_USERNAME=admin` before updating.

## Checks

Added regression tests for updates, authentication synchronization, log handling
and release packaging. A disposable installation verified initial startup, an
actual URL/port change, preserved users and client attributes, health checks and
repeated updates. The release reuses the commit's existing CI results.
