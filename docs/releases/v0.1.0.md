# KubePhos v0.1.0

First versioned open-source release of KubePhos, a platform for provisioning
Kubernetes infrastructure and running repeatable application experiments.

## Installation

- Linux installer generates independent service secrets and the initial administrator
  account, then starts the platform with Docker Compose.
- The installer archive pins the platform image to this release. Download
  `kubephos-v0.1.0.tar.gz`, verify it against `SHA256SUMS`, extract it and run
  `./install.sh --admin-email YOUR_EMAIL`.
- Development uses a separate Compose override, project, local credentials and port.
- Original KubePhos code is available under the MIT license; third-party components
  retain their own licenses.

## Infrastructure and catalog

- Proxmox connections, VM templates, Harbor, NFS and Kubernetes cluster provisioning.
- Per-VM Proxmox server placement, suggested VM IDs and network settings, and
  conflict validation.
- Cluster node migration and application-pool maintenance guarded against active
  experiments; control-plane and management pools remain fixed.
- Single-cluster and Cilium Cluster Mesh provisioning. Multi-cluster experiment
  execution is not implemented in this release.
- Application catalog includes Online Boutique, Bank of Anthos, Bookinfo,
  Train Ticket, muBench, LocalAI and Redis Cluster.
- Scheduler, descheduler and autoscaler integrations. TraDE and the orchestrator
  category are excluded; historical configurations and results are preserved.

## Experiments and results

- Private experiment configurations and experiments, with sharing to selected
  users or everyone, and consistent authorship metadata.
- Configuration wizards, editable comparison suites, individual-run results and
  aggregate comparisons between approaches.
- End-to-end Locust throughput and latency statistics, service metrics, SLO
  violations and aggregate scheduling/descheduling measurements.
- Updated plots, exports, processing logs and consistent light/dark interfaces.
- Experiment deletion removes associated runs, logs, results and artifacts, with
  retryable artifact cleanup.
- Application CPU/memory requests and limits are omitted when not configured.

## Release checks

Automated checks cover Go modules, frontend behavior and accessibility,
PostgreSQL storage/migrations, installer and packaging, and reachable dependency
vulnerabilities. The release workflow builds the platform and managed component
images, then publishes the installer archive and checksums.

See the installation guide before upgrading an existing instance. Back up the
PostgreSQL database, artifact storage and credential encryption key together.
