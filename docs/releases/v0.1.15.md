# KubePhos v0.1.15

## Telegram notifications

- Configure a dedicated Telegram bot in Administration → Notifications.
- Connect each user's private Telegram account from Account settings → Notifications,
  with preferences for experiment completion and failure and a test message.
- Notify only the experiment's author. Suites send one notification on completion
  or failure of the whole experiment.
- Encrypt bot credentials, use expiring connection links and persist notification
  delivery in PostgreSQL with retries. No public webhook is required.

## Cluster lifecycle and storage

- Publish missing managed component images to Harbor before Kubernetes bootstrap.
  New Harbor installations use the `kubephos` project; existing registry paths
  remain supported.
- Preserve managed storage, observability and platform ownership during cluster
  node maintenance, and recover cleanup targets after earlier maintenance failures.
- Track artifact uploads before writing to object storage so failed database
  updates do not leave untracked objects.
- Remove older unused KubePhos images during updates, preserving images referenced
  by containers and one previous image for rollback.
- Set the default Istio trace sampling percentage to 1% for platform provisioning.

## Interface

- Open comparison details on the Sources tab and remove warnings for differing
  experiment durations and load profiles.
- Standardize spacing between back navigation and page titles in resource details
  and editors.

## Upgrade

Back up the installation and wait for active work to finish. Set
`KUBEPHOS_VERSION=v0.1.15` in the installation `.env`, then run `./update.sh` from
this release's archive or checkout. Add `--directory /path/to/installation` for a
custom installation path. If using a temporary local image, restore
`KUBEPHOS_IMAGE=ghcr.io/unict-cclab/kubephos` first.

The updater applies migration 057 for Telegram settings, account connections and
the notification queue. Telegram remains inactive until an administrator
configures the bot. Connections are specific to each instance and are excluded
from configuration transfers. Existing experiment configurations, suites,
comparisons, results and credentials are retained. Managed component versions
are unchanged from v0.1.14.

## Verification

Go tests, static analysis and vulnerability checks; PostgreSQL storage, API and
worker integration tests; 534 frontend tests, production build, bundle and theme
checks; frontend dependency audit; installer tests, ShellCheck and Compose
validation. Telegram delivery is covered with a simulated API; real delivery
requires configuring a bot and connecting a Telegram account.
