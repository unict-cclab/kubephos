# KubePhos v0.1.4

## Resource connectivity

Proxmox connections, Kubernetes clusters, Harbor and NFS now have automatic,
read-only connectivity checks. Resource lists and details show **Not reachable**
after two failed checks and recover automatically when the connection returns.
Authentication failures, unavailable services and stale checks have distinct
states. Multi cluster details identify individual members; VM templates follow
their Proxmox connection. Monitoring does not change provisioning history or
resource modification dates.

## Cluster provisioning and access

- Retry failed cluster creation using saved settings and safe cleanup.
- Keep provisioning available when an unrelated Proxmox node is offline, and
  scope VM identifiers and ledger entries to their provider connection.
- Support Proxmox placement and provisioning activity for Harbor and NFS.
- Fix optional pool labels, Harbor authorization checks and ClusterMesh bootstrap.
- Isolate NFS volumes between clusters and retain diagnostics before rollback.
- Persist Cilium mesh settings across K3s reconciliation.
- Overlap independent cluster setup and avoid redundant image downloads.
- Download administrator SSH access keys; multi clusters use one shared key.
  Single/shared-key access now uses a compact download button.

## Interface and validation

- Improve table layouts, wizard navigation, field alignment and dark/light theme
  consistency. Keep actions visible at narrower widths.
- Add user email editing, deletion and temporary password resets; clear new-user
  forms between uses and require password changes on first login.
- Clarify dashboard access and keep labels, CPU units and authorship consistent.
- Preserve existing lists on incomplete API responses and show actionable errors.
- Validate JSON editor shapes and reject oversized, malformed or extra request
  values without exposing submitted secrets or internal network details.
- Use field names in application validation messages and reduce unnecessary work
  when building suite plots.

## Installation and maintenance

The updater checks pending work before replacing installed files, validates the
release before stopping services, and ignores unrelated checkout `.env` files.
HTTPS installations retain secure authentication cookies behind reverse proxies.
Unused examples and directory placeholders have been removed; documentation and
checks have been consolidated.

## Upgrade

Back up the installation first. In its `.env`, set `KUBEPHOS_VERSION=v0.1.4`, then
run `./update.sh` from the v0.1.4 archive or checkout. For a custom installation
path, add `--directory /path/to/installation`.

Database migrations are applied automatically. Existing users, credentials,
configurations and experiment results are retained. Connectivity checks start in
the worker after the update. State archives require a matching migration schema:
upgrade both instances before transferring state. Monitoring results and leases
are reset during state transfer.
