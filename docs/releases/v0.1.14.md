# KubePhos v0.1.14

## Istio Ambient

- Configure whether application services use the namespace waypoint by default,
  with overrides for individual services in experiments and independent deployments.
- Validate waypoint overrides against the application's services. Overrides that
  need routing through a Kubernetes Service are rejected if no matching Service
  is available.
- Keep the previous behavior for existing configurations: services use the
  waypoint unless explicitly configured otherwise. Services excluded from the
  waypoint remain in the ambient mesh through ztunnel.
- Show waypoint overrides in application configuration details.

## Interface

- Refine the Application tab layout and shared styles for resource controls,
  placement, Istio injection, service overrides and initial replicas.

## Upgrade

Back up the installation and wait for active work to finish. Set
`KUBEPHOS_VERSION=v0.1.14` in the installation `.env`, then run `./update.sh` from
this release's archive or checkout. Add `--directory /path/to/installation` for a
custom installation path. If using a temporary local image, restore
`KUBEPHOS_IMAGE=ghcr.io/unict-cclab/kubephos` first.

No new database migration is required. Existing configurations, suites,
comparisons, results and credentials are retained. Managed component versions
are unchanged from v0.1.13.

## Verification

Frontend regression tests and production build; bundle, theme and dependency
checks; Go tests and static analysis; isolated PostgreSQL tests for storage,
API and experiment execution; installer and packaging tests. Regression tests
cover waypoint routing overrides, validation and configuration controls.
